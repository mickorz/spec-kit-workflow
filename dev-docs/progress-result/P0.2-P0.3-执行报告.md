## P0.3 Test Runner

### 交付物

| 文件 | 用途 |
|------|------|
| `sdd/tools/run-tests.mjs` | 执行构建+测试，生成 evidence.json（三态语义） |
| `sdd/tools/freeze-baseline.mjs` | checkpoint 后冻结 approved-baseline.json |
| `sdd/tools/check-baseline.mjs` | 每轮 Test 前校验 spec/traceability/tasks 未被修改 |

### 三态语义设计

| status | 条件 | 退出码 | 后续行为 |
|--------|------|--------|---------|
| passed | 构建通过 + 测试全通过 | 0 | is-converged.mjs 判定收敛 |
| failed | 构建失败 / 测试失败 / 零测试 | 0 | append-findings.mjs 追加缺口任务 |
| error | Runner 自身异常 | 1 | 工作流中断（CHECK_FAILED） |

关键：测试失败时退出 0，而非 1。退出 1 仅用于 Runner 自身故障（配置缺失、文件写入失败等），不能冒充测试失败。

### evidence.json 结构

```json
{
  "feature": "login",
  "round": 1,
  "status": "failed",
  "build": { "passed": true, "command": "npm run build", "exitCode": 0, "output": "..." },
  "tests": { "passed": 0, "failed": 0, "total": 0, "command": "npm test", "exitCode": 0, "output": "..." },
  "failures": [{ "test": "none", "reason": "测试命令退出 0 但无实际测试执行记录" }],
  "fileHashes": [{ "file": "src/index.ts", "hash": "sha256-..." }],
  "generatedAt": "2026-10-13T..."
}
```

### 审批基线机制

```
checkpoint 人工审批通过
  -> freeze-baseline.mjs 保存 approved-baseline.json
     { approvedSpecHash, approvedTraceabilityHash, approvedTasksHash, status: "approved" }

每轮 Test 前
  -> check-baseline.mjs 比对当前文件哈希与审批基线
     匹配 -> 继续 Test
     不匹配 -> CHECK_FAILED，工作流中断
```

与 traceability.json 中的 specHash 区别：
- `specHash`（traceability.json 内）：工具计算的 spec.md 当前哈希，用于 Coverage Gate 比对
- `approvedSpecHash`（approved-baseline.json 内）：审批时刻冻结的 spec.md 哈希，用于防止审批后被修改

### glob 匹配修复

run-tests.mjs 的简化版 glob 曾不匹配 `src/**/*.ts` 到 `src/index.ts`（`**` 需匹配零层目录）。修复：改用字符级解析 `globToRegex`，`**/` 编译为 `(?:[^/]*/)*`（零或多层目录）。

## 工作流当前状态

```
Specify -> Plan -> Tasks -> Analyze
  -> freeze-traceability (填充 specHash)
  -> coverage (FR+NFR+AC+Tasks ID 集合校验)
  -> checkpoint (人工审批)
  -> freeze-baseline (冻结审批基线)
  -> Test
    -> check-baseline (校验基线)
    -> run-tests (生成 evidence.json)
```
