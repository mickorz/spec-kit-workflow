# Feature: 包含失败锁定机制的账号密码登录系统

## 概述

提供基于账号密码的登录认证能力，并引入失败次数累计与账号锁定机制，防止暴力破解。系统在用户连续输入错误密码达到阈值后自动锁定账号，锁定期间拒绝所有登录尝试，锁定到期后自动恢复可登录状态。覆盖正常登录、密码错误、账号锁定、锁定恢复、会话管理等完整流程，包含异常流程与边界条件处理。

## 功能需求

### FR-001: 账号密码登录

用户通过用户名（或邮箱）和密码进行登录认证。系统校验账号存在性、账号启用状态及密码正确性，校验通过后创建登录会话并返回认证凭证。

**验收条件**：

- AC-001: When 用户输入已注册且状态为启用的用户名和与存储密码哈希匹配的正确密码,
  the 登录系统 shall 登录成功并返回包含用户标识与过期时间的有效认证凭证。

- AC-002: If 用户输入不存在的用户名进行登录,
  the 登录系统 shall 拒绝登录并返回"用户名或密码错误"的统一错误提示，不泄露用户名是否存在。

- AC-003: If 用户输入已注册但状态为禁用的用户名进行登录,
  the 登录系统 shall 拒绝登录并返回"账号已被禁用"提示。

- AC-004: If 用户名或密码字段为空提交登录,
  the 登录系统 shall 拒绝登录并返回"用户名和密码不能为空"的参数校验提示。

- AC-005: When 密码正确且用户名大小写与注册时不一致,
  the 登录系统 shall 依据配置的大小写策略判定登录结果（策略为区分时登录失败，策略为不区分时登录成功）。

### FR-002: 密码错误处理

用户输入的密码与存储的密码哈希不匹配时，系统拒绝登录并累计该账号的连续失败次数，同时返回统一错误提示。

**验收条件**：

- AC-006: If 已存在且启用的账号输入错误密码,
  the 登录系统 shall 拒绝登录返回"用户名或密码错误"提示并将该账号失败计数加 1。

- AC-007: When 同一账号在一次失败后立即输入正确密码,
  the 登录系统 shall 允许登录成功并将失败计数清零。

- AC-008: If 密码错误发生,
  the 登录系统 shall 仅返回统一错误提示，不返回密码格式或哈希相关信息。

### FR-003: 失败次数累计与账号锁定

系统对每个账号维护连续登录失败次数计数器，当失败次数达到预设阈值时自动将该账号置为锁定状态，并记录锁定起始时间与锁定时长。锁定阈值与锁定时长为可配置参数。

**验收条件**：

- AC-009: When 账号失败次数累计达到锁定阈值（默认 5 次）,
  the 登录系统 shall 将该账号状态切换为锁定，后续登录请求被直接拒绝并返回"账号已锁定，请于 X 分钟后重试"提示（X 为剩余锁定时间）。

- AC-010: While 账号处于锁定状态期间,
  the 登录系统 shall 拒绝该账号的一切登录请求（即使输入正确密码）且不再增加失败计数。

- AC-011: Where 锁定阈值配置被修改,
  the 登录系统 shall 对新触发的锁定应用新阈值（阈值最小值为 3，配置低于 3 时按 3 处理）。

- AC-012: Where 锁定时长配置为 0（配置单位为分钟，默认 15 分钟）,
  the 登录系统 shall 将账号置为永久锁定，仅管理员手动解锁可恢复。

### FR-004: 锁定状态判定与恢复

系统在每次登录请求前判定账号锁定状态：若锁定未到期则拒绝登录；若锁定已到期则自动解锁账号并清零失败计数，恢复可登录能力。

**验收条件**：

- AC-013: When 账号锁定时长到期后的下一次登录请求发生（无论密码正确与否）,
  the 登录系统 shall 自动解锁该账号、清零失败计数并恢复可登录状态。

- AC-014: If 锁定剩余时间不足 1 秒,
  the 登录系统 shall 仍视为锁定中（锁定时长精确到秒级判定，满 1 倍锁定时长后解锁）。

- AC-015: If 账号为永久锁定（锁定时长配置为 0）,
  the 登录系统 shall 使账号经过任意时长仍保持锁定。

- AC-016: When 同一账号经历锁定到期后再次失败达到阈值（锁定到期再失败再锁定循环）,
  the 登录系统 shall 独立计算每次锁定周期且锁定时长不叠加。

### FR-005: 管理员手动解锁

管理员可通过管理接口手动解锁指定账号，立即清除锁定状态并重置失败计数，不受锁定时长是否到期限制。

**验收条件**：

- AC-017: When 管理员调用解锁接口传入已锁定的有效账号标识,
  the 登录系统 shall 立即清除该账号锁定状态并将失败计数归零，账号恢复可登录。

- AC-018: If 管理员调用解锁接口传入不存在的账号标识,
  the 登录系统 shall 返回"账号不存在"错误且不产生副作用。

- AC-019: When 管理员对未锁定账号调用解锁接口,
  the 登录系统 shall 幂等成功处理且账号状态与失败计数不变。

- AC-020: If 非管理员角色调用解锁接口,
  the 登录系统 shall 返回"无权限"错误并拒绝执行。

### FR-006: 密码安全存储与校验

用户密码以不可逆哈希形式存储，登录校验时对输入密码做相同哈希后与存储值比对，全程不接触明文密码。哈希算法采用带盐值的慢哈希算法（如 bcrypt / argon2）。

**验收条件**：

- AC-021: The 登录系统 shall 以带盐值的哈希形式存储密码（数据库中不含明文，相同明文密码因不同盐值产生不同哈希）。

- AC-022: When 登录校验执行时,
  the 登录系统 shall 对输入密码做相同哈希处理后与存储哈希比对，比对结果一致即判定密码正确。

- AC-023: Where 密码哈希算法或盐值生成方式被配置替换,
  the 登录系统 shall 要求历史账号按迁移策略重新设置密码或支持旧算法兼容校验。

### FR-007: 登录会话与凭证管理

登录成功后系统创建会话并签发认证凭证，凭证携带过期时间；凭证过期后需重新登录。支持主动登出使凭证失效。

**验收条件**：

- AC-024: When 用户携带过期时间之前的凭证发起后续请求,
  the 登录系统 shall 通过该凭证的认证校验。

- AC-025: If 凭证超过过期时间,
  the 登录系统 shall 使其失效并对其请求返回"登录已过期，请重新登录"。

- AC-026: When 用户主动调用登出接口,
  the 登录系统 shall 立即使该凭证失效并拒绝后续使用该凭证的请求。

- AC-027: Where 同一账号在多设备并发登录,
  the 登录系统 shall 按可配置的会话策略处理（允许多会话或后者挤掉前者）。

## 非功能需求

### NFR-001: 密码存储安全性

密码存储必须使用带盐值的慢哈希算法，禁止以明文、可逆加密或无盐哈希（如裸 MD5/SHA1）存储密码。哈希计算开销应使单次校验耗时不低于可配置下限，以增加暴力破解成本。

**验收条件**：

- AC-028: The 登录系统 shall 使用带盐值的慢哈希算法（bcrypt、argon2 或同等强度）存储密码，禁止明文、可逆加密或无盐哈希。

- AC-029: The 登录系统 shall 保证单次密码哈希校验耗时不低于可配置下限（默认 100ms）。

### NFR-002: 登录接口响应性能

正常登录请求（不含哈希计算异常情况）95 分位响应时间不超过 500ms，99 分位不超过 1000ms。账号锁定判定与失败计数更新操作不得显著拖慢登录主流程。

**验收条件**：

- AC-030: The 登录接口 shall 保证正常登录请求 95 分位响应不超过 500ms 且 99 分位不超过 1000ms，账号锁定判定与失败计数更新不显著拖慢登录主流程。

### NFR-003: 防暴力破解能力

失败锁定机制需有效抑制暴力破解：单账号连续失败达阈值即锁定；系统应支持基于 IP 的登录失败频率限制（可选增强）。锁定参数应可在不重启服务的情况下动态调整。

**验收条件**：

- AC-031: The 登录系统 shall 支持单账号失败阈值锁定与可选的基于 IP 的失败频率限制，且锁定参数（阈值、时长）在不重启服务的情况下动态调整。

### NFR-004: 审计日志

系统对登录成功、登录失败（含失败次数）、账号锁定触发、账号自动解锁、管理员手动解锁、登出事件记录审计日志。日志包含时间戳、账号标识、来源 IP、事件类型与结果，日志不可被普通用户篡改，保留期限不少于 90 天。

**验收条件**：

- AC-032: The 审计日志系统 shall 记录登录成功、登录失败、账号锁定触发、账号自动解锁、管理员手动解锁与登出事件，日志含时间戳、账号标识、来源 IP、事件类型与结果，保留期限不少于 90 天且不可被普通用户篡改。

### NFR-005: 错误提示安全性

所有登录相关错误提示不得泄露系统内部信息，包括但不限于：用户名是否存在、密码格式校验细节、哈希算法信息、数据库错误。对外统一返回业务级提示，技术细节仅记录于服务端日志。

**验收条件**：

- AC-033: The 登录系统 shall 对外仅返回业务级错误提示，不泄露用户名是否存在、密码校验细节、哈希算法信息或数据库错误等内部信息。

## 公共 API 契约

所有实现必须导出以下 TypeScript 模块，隐藏验收测试将直接导入这些接口：

```typescript
// src/auth.ts — 登录认证主模块

export interface LoginResult {
  success: boolean
  token?: string
  error?: string
  remainingLockTime?: number  // 锁定剩余秒数
}

export interface LockStatus {
  locked: boolean
  failedAttempts: number
  lockedAt?: number  // 锁定起始时间戳(ms)
  lockDurationMs?: number
}

// 登录认证
export function login(username: string, password: string, ip: string): LoginResult

// 获取锁定状态
export function getLockStatus(username: string): LockStatus

// 管理员手动解锁
export function adminUnlock(username: string, adminUser: string): { success: boolean, error?: string }

// 登出（凭证失效）
export function logout(token: string): boolean

// 验证凭证
export function verifyToken(token: string): { valid: boolean, expired?: boolean }

// 注册用户（测试辅助）
export function registerUser(username: string, password: string, opts?: { disabled?: boolean }): void

// 获取审计日志
export function getAuditLogs(username?: string): Array<{
  timestamp: number
  username: string
  ip: string
  event: string
  result: string
}>

// 获取密码哈希（验证存储安全性）
export function getPasswordHash(username: string): string | null

// 配置更新（锁定参数动态调整）
export function updateLockConfig(opts: { threshold?: number, durationMs?: number }): void

// 重置状态（测试隔离用）
export function resetState(): void
```

实现注意：
- 密码哈希必须使用 bcrypt 或同等强度的带盐慢哈希
- 审计日志必须包含来源 IP 字段
- 锁定阈值和时长必须可通过 updateLockConfig 动态调整
- registerUser 和 resetState 是测试辅助函数，不影响需求验收
